**Order matters in path B.** `promotion-check` and `release.yml` both refuse a promotion whose version is
already tagged, so the `main` to `prod` merge (steps 3–4) goes first and the tag is created last, at the
promoted SHA. Creating the release first would leave `prod` unable to take the promotion PR.

### What cannot run without GitHub Actions

- `release.yml` as a whole: the in-workflow gate, the attestation of the checksums, the attestation of the
  SBOM, the draft upload and the publish.
- `promotion-check.yml`, and the four required checks on `main` (`gate`, both `codeql` jobs,
  `dependency-review`). Their absence is why step 1 is an admin landing.
- Attestation. It cannot be produced from this machine at all.
- The hosted proof that `install.sh` works from the published assets. `release accept` does the same install
  in a throwaway home locally (`accept.ts`), so the proof moves to step 7B and step 9.

### What a user loses without attestation

- `install.sh` and `splice upgrade` stop at the attestation check for anyone with `gh` signed in (`install.sh:249-253`,
  `UpgradeRelease.kt:62`). They work with `gh` signed out or not installed, because checksums are still checked.
- As the newest release that is not a prerelease, `v0.4.0` becomes `latest`, so the README one-liner that
  fetches `releases/latest/download/install.sh` fails for those users. Publishing it as a prerelease would keep
  it off `latest` but is a different release from the one Marcos asked for; his call.
- Each asset is bound to the release by `sha256sums.txt` alone. `gh attestation verify` on the jar fails.
- The "releases attested" badge and the sentence "every release is … provenance-attested" in the README
  become false for this release. The patch is in the scratchpad (`README.unattested.delta.diff`).
- The release notes should say so in the first lines, as `0.4.0-beta.1`'s did, with the two ways in: install with
  `gh` signed out, or download `splice.jar` and `splice-launch`, check them against `sha256sums.txt`, and run
  `SPLICE_JAR=./splice.jar ./install.sh`. Whether `SPLICE_JAR` mode also installs the Linux hub binaries is not
  verified here.
