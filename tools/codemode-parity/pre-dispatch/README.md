This dedicated Linux witness observes cancellation before source dispatch readiness. It does not replace the existing interruption case, which requires a delivered notification, and it is not registered for source or parity credit.

`executePreDispatchWitness` and `preDispatchWitnessFindings` are exported by `../current-pre-dispatch-proof.ts`. The caller supplies the canonical source-build receipt and inventory, exact candidate JAR, verified sibling native host, pinned Java/Bun/GDB executables, and an explicit cached Kotlin 2.3.21 compiler plus every compiler classpath dependency. The input contract hash is independent of the fresh 32-hex run ID.

The source driver launches the actual instrumented CLI on an owned PTY against a deterministic loopback server. It starts through a same-PID `env` wrapper and a ptrace exec catchpoint. Three hardware application breakpoints park the readiness writer before mutex acquisition, observe the actual select-poll closure, and observe `remove_dispatch_gate`. Actual Ctrl-C cancels the pending callback while the readiness writer remains parked. The ordinary native turn abort and resumed user turn must retain completed storage and discard interrupted storage. GDB's internal shared-library loader software breakpoint is retained and disclosed in raw MI; there is no claim that all debug-time instruction bytes remain unpatched. No values, source, packets, return values, or application control-flow calls are replaced.

The candidate fixture transparently decorates the public notification receiver with a cancellable permit. Actual `observe` entry proves provider ownership was registered. Foreground request cancellation alone leaves the session-owned callback active. The packaged production HTTP probe must return 401 for anonymous and session keys, then 200 for the management key and terminate exactly the owned cell. The pending delivery must cancel before the permit is released. Actual same-conversation native completion must show storage rollback; releasing the permit afterward must forward nothing. This public delivery boundary differs from the source Rust watch gate.

Each execution keeps raw MI, PTY bytes, source rollout events, actual PID/start-time/executable identities, full canonical LLVM export and mappings, candidate source/compile/bytecode identities, production class origins, both raw HTTP/2 directions, ordinary gateway history and retained records. The offline decoder uses the candidate's packaged HPACK implementation and pinned native protobuf descriptor. The verifier replays the standard LLVM exporter/decoder and native protobuf decoding from raw bytes. Missing or changed evidence fails; incidental function entries receive no credit.

The source, LLVM exporter and candidate each run in isolated user scopes with MemoryMax=4GiB, MemorySwapMax=0, a finite wall timeout, low CPU priority and idle IO priority. The source driver attests the actual inferior PID, requires multiple Tokio workers and only cleans descendants with matching recorded lifetimes. Candidate cleanup is limited to the exact attested native PID/start-time. All homes, state, profiles and temporary host payloads are case-local. No Gradle, real inference, Claude session, installed daemon or production control endpoint is used.

Focused evidence guards: `bun test tools/codemode-parity/current-pre-dispatch-contract.test.ts`. Drivers have a separate `tsconfig.json` so their standalone entry points are checked without changing the existing parity tooling project.
