# Disk and privacy

What Splice writes on your machine, who can read each file, how long it stays, and how to remove all of it. Every path below is local: nothing here is uploaded unless you turn on an export yourself.

## At a glance

| Place | What lives there | Mode |
| --- | --- | --- |
| `~/.config/splice/` | `splice.toml` (topology), `keys.toml` (API keys), `auth/` (subscription sign-ins) | credentials 0600 |
| `~/.splice/state/` | management key, runtime settings, config backups, saved Claude logins, traces, journals | directory 0700 |
| `~/.splice/logs/` | `daemon.log`, `daemon-boot.log` | directory 0700 |
| `~/.claude-<head>/` | each head's Claude Code config folder, written at launch | see [Claude Code's directories](#claude-codes-directories) |
| `~/.local/share/splice/`, `~/.local/bin/` | the jar, the `splice-launch` shim, release copies, the command links | see [Install, upgrade and diagnostics](#install-upgrade-and-diagnostics) |

A pre-0.4 install may keep `~/.claude-codex/state` instead of `~/.splice/state`; `[daemon] state_dir` or `SPLICE_STATE_DIR` selects another state directory.

## What splice keeps on your disk

Performance collection keeps its statistics, request evidence, objectives, and configuration history in the local state directory. Collection and export are separate: metrics, traces, or logs are sent only when the operator enables performance export and configures its destination and signal set. Full profile captures are separate, explicit requests that create a local downloadable artifact; they are not part of the metrics/trace/log exporter.
New installs keep state in `~/.splice/state` and logs in `~/.splice/logs`. A pre-0.4 install can
keep `~/.claude-codex/state` and its logs; `[daemon] state_dir` or `SPLICE_STATE_DIR` can select
another state directory. State and log directories are owner-only (0700) at daemon start, but a
custom state directory's parent is not made owner-only.
Topology, API keys and subscription sign-ins normally live in `~/.config/splice`. The management
key, runtime settings, config backups and saved Claude logins live in the state directory.
Every credential splice writes is 0600. splice also writes into the Claude Code config directories it launches
(`~/.claude-<head>/`), and the install lives in `~/.local/share/splice` and `~/.local/bin`. Each head keeps to its own
folder. Outside them, `splice desktop on` writes one configuration of splice's into Claude Desktop's configuration
library, at your command, and `splice desktop off` takes it out; the gateway configuration holds no key.
`splice desktop on` or `splice desktop off` writes `~/.claude/settings.json` only when removing settings left
by an older Splice Desktop setup. It preserves the other Claude Code settings.

"Only you" below means owner-only: the file is 0600, or it sits inside an owner-only state or log directory.
The tables use new-install defaults, with the state root at `~/.splice/state`. On an install upgraded from
before 0.4 that kept its `~/.claude-codex/state`, that adopted folder is the state root in every row, and a
selected state root changes those paths too.
"Your umask" means the file gets your account's default permissions, usually readable by other
local accounts unless its directory prevents it. The last column names the source file that writes
it; a check in the build (`DiskWritesLawTest`) fails when any source file writes a file this section
does not name, and when a file it names gains a write the check has not recorded, so each new write is
read against its row. It reads Kotlin sources, so it misses a write through a library handed a path,
a shell redirect to an unquoted or literal path, reflection, and files written by programs splice starts.

## Credentials and file modes

Every credential Splice writes is created owner-only (0600) and written atomically: the bytes go to an owner-only temporary file beside the target, which is then renamed over it, so a token file is never readable by other accounts, even for a moment, and a concurrent reader never sees half a file. The state and log directories are made owner-only (0700) each time the daemon starts.

| Secret | Where | Written by |
| --- | --- | --- |
| Subscription sign-ins (ChatGPT, Grok, Kimi, Muse) | `~/.config/splice/auth/<provider>.json` | `splice login <head>` or `<command> login` |
| API keys | `~/.config/splice/keys.toml` (0600), or the daemon's own environment | `splice key set NAME [--stdin]`, `<command> login` |
| Additional Claude logins | `~/.splice/state/claude-accounts/<head>/<label>/` | `splice login <head> --label <name>` |
| Control-plane key | `~/.splice/state/mgmt-key` | the daemon when it is missing; `splice rotate-key` replaces it |

Each of these is password-equivalent: anything that can read the file can spend against your account. Never commit or paste them. Splice never reads a vendor CLI's own credential file (`~/.codex/auth.json` and the like) unless you name it in a provider's `auth.file`. The full table, with each backend's auth kind, is in [Credential locations](providers-and-accounts.md#credential-locations).

## Claude Code directories

Splice launches Claude Code with its config directory set to `~/.claude-<head>/`, one folder per head, so no head's settings, hooks or sessions leak into `~/.claude` or into another head. What it shares with `~/.claude` (agents, commands, skills, hooks, plugins, `CLAUDE.md`, and optionally `sessions` and `projects`) is linked, not copied. The deprecated `claude` head is the one exception: it runs over `~/.claude` itself, which Splice does not rewrite. Every file Splice puts in these folders is listed in [Claude Code's directories](#claude-codes-directories) above.

## Opt-in capture

Two kinds of capture hold whole conversations. Both are set per head under `[heads.<key>.overrides]` only; `[defaults]`, an environment variable or a runtime PATCH cannot turn them on everywhere.

| Capture | Where | Default | Read with | Turn off or clear |
| --- | --- | --- | --- | --- |
| Wire tap (`wireTap`) | memory only, never disk | `0`, keeps none | `splice wire <head> [--last N] [--json]` | remove the key; a restart forgets it |
| Request/response trace (`trace`) | `~/.splice/state/trace/<head>-<day>.jsonl`, owner-only | on for every head; credentials redacted | `splice trace <head> [--last N] [--session S] [--turn ID] [--json]` | `trace = "false"`; `splice trace <head> --purge` deletes the day files |

While a wire tap is on, `splice doctor` names the head on every run. Set it on one head while you audit what Splice sends, read it, then remove it:

```toml
[heads.example.overrides]
wireTap = "20"
```

Trace day files older than `traceRetentionDays` (default 7) are deleted, and a body longer than `traceMaxBodyChars` is cut with a note in the record.

Performance export (metrics, traces or logs over OTLP) sends nothing until you enable it and configure a destination and signal set. `splice doctor --json` builds a support report on your machine (no credential, account id or working directory in it) and uploads nothing; `--with-logs` adds the redacted log tail.

## Clean uninstall

`splice uninstall` (the same as `splice uninstall --all`) removes what makes Splice run, and leaves your data:

| Removed | Left on disk |
| --- | --- |
| every head command, `splice` and `claude-splice` in `~/.local/bin` (your own `claude` stays) | the jar and shim in `~/.local/share/splice/` |
| on Linux, the systemd user units and sockets Splice laid (stopped, disabled, removed) | `~/.config/splice/` (topology, keys, sign-ins) |
| Splice's `/login` command in `~/.claude` (one you wrote stays) | `~/.splice/state/` and `~/.splice/logs/` |
| Claude Desktop's Splice configuration, put back as before `splice desktop on`, and the `Claude (Splice)` app launcher | each head's `~/.claude-<head>/` folder |

`splice uninstall <head>` removes one head's command and leaves the units, since `splice.toml` still names that head.  If `claude` itself is wrapped, uninstall leaves it and says how to unwrap it (`POST /api/claude-head/unwrap` on the control plane).

Before discarding any data, open `splice.toml` and identify each `[heads.<key>]` folder. The default is
`~/.claude-<key>/`; check the head's `[heads.<key>.claude] config_dir` for a custom path. The plain `claude`
head may use `~/.claude` itself: keep that shared directory. Don't assume a folder belongs to Splice because
its name starts with `.claude-`.

Inspect each confirmed folder and back it up to a private location outside the folders you intend to discard.
A head with `isolate = ["projects"]` may hold the only copy of its transcripts; a pre-0.4 install may also
keep its state under `~/.claude-codex/`. Check that the backup contains the transcripts and state you need.
After uninstall, move confirmed head folders to the trash one at a time by their exact paths, and leave
unrelated profiles and shared data alone.

For a default install, once you've backed up what you want to keep and confirmed you want to discard all
three Splice roots, move them to the trash:

```bash
trash ~/.local/share/splice ~/.config/splice ~/.splice
```
