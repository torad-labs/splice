# CLI & Control Plane API Reference

Use `splice` to connect providers, launch clients, inspect sessions, and operate the daemon. Use the HTTP reference to find the right listener, path, and credential for a script or integration.

[Setup and lifecycle](#setup-configuration-and-lifecycle) · [Accounts and launchers](#accounts-launchers-sharing-and-remote-commands) · [Diagnostics](#status-diagnostics-and-console-controls) · [HTTP API](#http-api) · [Listeners and ports](#listeners-and-credentials)

## Everyday commands

Use `splice setup` to connect a plan or API key, choose launchers and Modes, and sign in. After an upgrade, `splice setup --update` offers what's new without asking for your plans again.

```bash
splice status
splice doctor --json
splice sessions --json
splice perf --window 24h
splice usage --json
splice logs --tail 50
```

A named subscription launcher accepts `login` as its first argument: `claudex login`, `claude-grok login`, `claude-kimi login`, or `claude-muse login`. To add more curated OpenRouter models to your OpenRouter head, run `splice add-model`.

## Dispatch and help

Optional switches are off unless stated otherwise. Values after named options are separate arguments unless an equals form is listed. Arguments forwarded to Claude Code, Claude Desktop, or an MCP child are not splice options.

- The installed `splice` is a link to `splice-launch`. The shell selects the command by its invoked basename (or `SPLICE_HEAD`); it sends admin argv to the jar except for `splice launch claude`, which becomes a `claude-splice` launch in the same shell. Running the jar directly bypasses that shell dispatch. [splice-launch](../../app/src/main/dist/bin/splice-launch):300–332, 497–553
- `splice` with no arguments prints the start menu if the JVM sees a console; without one it boots the daemon. `splice help`, `splice -h` and `splice --help` print the start menu, not per-verb help. For Kotlin-registered verbs, `-h` or `--help` anywhere before the first `--` prints that verb's usage without acting. `--` stops **help detection**, not all option parsing; a command must implement its own literal-argument handling. Unknown verbs and top-level parse misses exit 2; delegated validators have their own return codes. There is no global `--version` alias. [Main.kt](../../app/src/main/kotlin/splice/app/Main.kt):72–86; [Cli.kt](../../app/src/main/kotlin/splice/app/cli/Cli.kt):13–27, 75–99; [CommandParser.kt](../../app/src/main/kotlin/splice/app/cli/CommandParser.kt):65–79, 268–282
- `splice daemon [--stderr-is-boot-log]` runs the daemon in the foreground. The internal switch says stderr already goes to the boot log. `splice start` starts or reuses the supervisor service when that service owns the install; otherwise it runs the daemon here. Neither first-word route uses normal CLI help or validates a trailing argument list; direct daemon startup only tests membership of that boot-log switch. [Main.kt](../../app/src/main/kotlin/splice/app/Main.kt):72–86, 231–238; [LifecycleWiring.kt](../../app/src/main/kotlin/splice/app/LifecycleWiring.kt):76–81; [DaemonColdStart.kt](../../features/lifecycle/src/main/kotlin/splice/lifecycle/start/DaemonColdStart.kt):44–58; [DaemonLaunch.kt](../../features/lifecycle/src/main/kotlin/splice/lifecycle/start/DaemonLaunch.kt):219–221

### Providers and models

- `splice add <profile> [--name NAME] [--base-url URL] [--model ID[:WINDOW]]... [--command CMD] [--key provider or new] [--live] [--yes or -y]` adds a head and links its command. Required profile is one of `codex`, `grok`, `kimi`, `muse`, `deepseek`, `openrouter`, `claude`, `local`, `api-key`; a profile's nonempty default command is also an alias (respectively `claudex`, `claude-grok`, `claude-kimi`, `claude-muse`, `claude-deepseek`, `claude-openrouter`, `claude`; none for the last two). [AddArgs.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddArgs.kt):12–81; [AddProfiles.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddProfiles.kt):132–145; [AddProfileCatalog.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddProfileCatalog.kt):47–465
  - `--name` is the new topology key, default profile key, but the `local` and `api-key` presets require an explicit name. `--command` is the launcher basename, default profile command or `claude-<key>` if the profile's command is blank. `--base-url` overrides the profile endpoint; the local profile tries a uniquely detected endpoint if omitted, and the generic API-key profile needs an endpoint. [AddPrepare.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddPrepare.kt):99–107, 210–229, 240–267; [AddProfileCatalog.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddProfileCatalog.kt):436–473
  - Repeat `--model` to give model rows instead of the profile roster; the first is pinned on a non-client-roster head. Only an integer suffix after the last colon is read as a window. Without it, use the profile row's window if known or 128,000 tokens otherwise. With no explicit rows, use the profile roster or ask for rows if it has none. [AddModels.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddModels.kt):18–80; [AddProfiles.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddProfiles.kt):154–175
  - `--key provider` reuses the provider credential for a second command on that endpoint; `--key new` creates a separate provider in the same family. No implicit choice: asks or refuses if unanswered. `--live` runs one short turn after saving/activation; otherwise the prompt defaults to no. `--yes`/`-y` accepts ordinary defaults without asking, not the credential-choice question. The endpoint presets are Codex `https://chatgpt.com/backend-api/codex`, Grok `https://api.x.ai/v1`, Kimi `https://api.kimi.com/coding`, Muse `https://api.meta.ai/v1`, DeepSeek `https://api.deepseek.com/anthropic`, OpenRouter `https://openrouter.ai/api/v1`, and Claude `https://api.anthropic.com`; `local` and `api-key` have no fixed address. [AddArgs.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddArgs.kt):18–55; [AddPrepare.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddPrepare.kt):161–207; [AddCommand.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddCommand.kt):60–80, 110–133
- `splice add provider <file-or-URL> [--check]` installs a custom provider definition into the topology. The required source is a local file (supports home expansion), HTTPS URL, or loopback HTTP URL; no redirects. Default installs; `--check` validates the schema and merge without writing, not whether the definition is safe. Install a provider with `auth.kind = "command"` only if you trust its command as a shell script: it runs with the daemon user's permissions. The literal `provider` selects this grammar only in first position after `add`. [AddCommand.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddCommand.kt):41–51; [AddProviderCommand.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddProviderCommand.kt):42–67, 117–145; [DefinitionSource.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/DefinitionSource.kt):30–59
- `splice add-model` takes no args; interactive selection of a supported configured head and catalog model rows, then writes the selection. `splice models [provider] [--all]` compares each configured provider's roster to its declared rows; optional provider key restricts it to one. Default prints all declared and at most eight undeclared rows per provider; `--all` shows the rest. [CommandParser.kt](../../app/src/main/kotlin/splice/app/cli/CommandParser.kt):160–165; [AddModels.kt](../../features/configuration/src/main/kotlin/splice/configuration/add/AddModels.kt):94–133; [ModelsCommand.kt](../../features/models/src/main/kotlin/splice/models/list/ModelsCommand.kt):15–56, 95–114

**What `splice add <profile>` checks.** The profile supplies what it knows. For a generic OpenAI-compatible endpoint, provide the base URL and model rows on the command line or when prompted. If it needs a credential, splice uses the same sign-in flow as `splice login`. Before saving, splice verifies parsing, credentials, endpoint reachability, model IDs and published window sizes where available. It saves with one rename, links the command, and offers a restart if the daemon is running. A refusal before the save leaves the topology file byte-identical. `--live`, or yes at the optional prompt, runs one short turn through the installed command after saving; a failed live check reports why and leaves the head saved.

### Local inference door and per-head listeners

**Local door aliases on the control port.** Both prefixes register the same methods and delegate to the same service. A caller presents the **terminal key or Desktop key** as `Authorization: Bearer` or `x-api-key` (Authorization takes precedence); the identified caller's lane must be open. These are not the operator routes. The daemon opens its door before binding control; the mount answers 401 if there is no opened service. See [DesktopRoutes.kt](../../app/src/main/kotlin/splice/app/control/DesktopRoutes.kt):73–87,146–154, [DaemonDesktop.kt](../../app/src/main/kotlin/splice/app/desktop/DaemonDesktop.kt):141–157,228–231 and [DesktopDoor.kt](../../app/src/main/kotlin/splice/app/desktop/DesktopDoor.kt):74–141,166–177.

**Head HTTP.** [HeadEngine.kt](../../features/turns/src/main/kotlin/splice/head/HeadEngine.kt) and [ClientAuth.kt](../../features/turns/src/main/kotlin/splice/head/ClientAuth.kt). Head auth is separate from local control auth. **Head caller** means the turn or management key (bearer or `x-api-key`) on heads that hold the upstream credential. On client-auth heads, Splice keys cannot be forwarded; if the head holds a login pool, the caller needs valid launch proof or a login already held in that pool. A forwarding-only head also requires an upstream credential for actual turns, not for the local reads/count. Foreign `Host` headers are refused before routing. There are no per-head `/mgmt/*` or console mounts.

### Native MCP front

The front is a distinct optional HTTP listener, not a second general control API. Use its MCP access bearer on `/mcp/*` and the management bearer (not the console key) on its narrow holder-control paths. Its daemon callbacks are the loopback `/api/mcp/hub/*` rows above. The front can temporarily refuse fresh work while performing an in-place upgrade. See [Main.kt](../../integrations/mcp-hub/src/linuxX64Main/kotlin/splice/hub/front/Main.kt):90–105,131–172,393–404,486–489 and [Hub.kt](../../integrations/mcp-hub/src/linuxX64Main/kotlin/splice/hub/front/Hub.kt):439–460.

| --- | --- |
| `POST /mcp/{name}`, `GET /mcp/{name}`, `DELETE /mcp/{name}` | MCP access bearer. Submit MCP messages, open the event stream, or end the session. The native dispatcher uses the nonempty suffix after `/mcp/` as the server name. |
| `POST /mgmt/mcp/holders/drain`, `DELETE /mgmt/mcp/holders/drain` | Management bearer. Pause or resume admission for a retained holder. |

### Metrics at a glance

The local Prometheus scrape is `GET /api/perf/metrics`; the remote admin scrape is `GET /server/metrics`. Console assets, browser-side navigation and upstream/client URLs are not additional API registrations; temporary sign-in callback listeners (e.g. [OAuthLoginFlow.kt](../../integrations/oauth/src/main/kotlin/splice/oauth/OAuthLoginFlow.kt):95–120) are not persistent daemon routes.
