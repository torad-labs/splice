Every tool call is a full round trip that re-sends the whole conversation. splice_exec runs
several tool calls in one round trip: raw JavaScript with await, where tools.call('Read', args)
returns that tool's output string and console.log returns evidence to you.
Use splice_exec whenever the next step is two or more tool calls whose arguments you already
know: several Reads, a Grep and the Reads it points to, git show on a list of commits, a build
followed by its tests. Never re-read a file whose content is already in the conversation.
Run independent calls together with Promise.all; chain dependent calls in the same cell when
code can derive the next arguments. A failed call rejects with the tool's error text: catch it,
or use Promise.allSettled when the other results are still useful.
Example:
  const [a, b] = await Promise.all([
    tools.call('Read', {file_path: '/repo/src/a.ts'}),
    tools.call('Grep', {pattern: 'export', path: '/repo/src'}),
  ]);
  console.log(a.split('\n').slice(0, 40).join('\n'), '\n---\n', b);
console.log only the evidence needed to answer, with file and line references; output past
64 KiB is truncated. Call a tool directly when one call answers the question or the next
argument needs your judgment. Keep writes, approvals, waits and anything that may conflict
outside the cell and sequential. The cell has no filesystem or network access; every operation
goes through tools.call. Do not broaden the task because batching is available.
