# Decisions & Caveats

- **CI upgrade-source selection** (autonomous decision, 2026-11-24T14:31): e2e-docker.yml picks the greatest stable release strictly below the candidate's core version from the splice.torad.ai release index (CDN-hosted, sha256-verified), and keeps a separate explicit v0.3.2 legacy run. Modern sources (>=0.4) dispatch to upgrade-064.sh; pre-0.4 to the legacy upgrade.sh.
  - Rationale: v0.6.3/v0.6.4 have no GitHub assets, so the old asset filter always fell back to v0.3.2. Strictly-below selection gives v0.6.3 today (main=0.6.4) and v0.6.4 automatically after the 0.7.0 bump, without committing any version bump.
  - Caveat: The GitHub fallback is taken only on a CDN 404 for the manifest; any other CDN failure or checksum mismatch fails the run rather than silently falling back.
- **Sibling heads sharing a provider** (autonomous decision, 2026-11-24T15:12): check-config --fix offers to move head-held context_window, model_slots and per-head knobs to the provider only when every head on that provider would be served the same afterwards (the rule the standing-prompt move already followed); a head's launch uses its own pinned_model.
  - Rationale: A 0.6.4 multi-head probe showed the move silently changing a sibling head's maxInflight/window/tiers and the sibling launching on the provider's model rather than its own pin — both regressions against 0.6.4 behaviour.
  - Caveat: When siblings disagree, the head-held warning remains with no automatic move; the user keeps the head-held value until they reconcile the heads.
- **Pre-upgrade recipes keep their key helper** (autonomous decision, 2026-11-24T17:51): When the gateway relaunches a head, the head folder's settings.json keeps apiKeyHelper. The new session switches the helper off in its own --settings overlay ({"apiKeyHelper":"","spliceLaunch":true}).
  - Rationale: Recipes saved by 0.6.3/0.6.4 get their bearer only from the head folder's helper. Removing it made them replay as "Not logged in" after the candidate relaunched the head (Docker rehearsal 76/77). The overlay keeps what the newer change was for: gateway sessions send only the gateway key.
  - Caveat: This was checked against Claude Code 2.1.331: with the empty helper in the overlay, only the environment bearer was sent. A future client that treats an empty apiKeyHelper differently would need another look.
- **Verification scope and bug C** (autonomous decision, 2026-11-24T17:51): Marcos ordered the campaign finished by one fast worker with no extra verification loops, so no separate cross-lab verifier was run. Builders came from two labs (Sol for the shell/CI work, Opus for the Kotlin work). The proof is the Docker receipts: v0.6.4 (shim-27) -> 0.7.0-e2e (shim-30) PASS 77/77, v0.6.3 -> 0.6.4 PASS 77/77, v0.3.2 legacy PASS 53/53. Mac Gradle checks and all repo gates are green. Bug C (check-config --fix offers again a warning that has nothing to move) is left as is.
  - Rationale: Direct order from Marcos. Bug C is minor: those warnings still offer remove/set-value, and pressing s already moves on.
  - Caveat: The 0.7.0-e2e jar was a scratch build that was never committed. The version stays at 0.6.4 on main. After the 0.7.0 bump, CI selects v0.6.4 as the source on its own.
